# Python Responses memory contract / Python Responses 记忆合同

2026-09-13, next slice after the separately frozen TypeScript AI SDK acceptance. The original 24-case acceptance is superseded by the independent endpoint/dispatch/acknowledgement review; the final v6 has passed 30 Responses cases, 12 frozen base SDK cases and one retained legacy wheel case; exact artifacts are in VERIFICATION.md. Exact artifacts and the independently built source-frozen helper are recorded in VERIFICATION.md.

The selected official entry is OpenAI Python **3.13.0**, Python >=3.10, `OpenAI` / `AsyncOpenAI` Responses. This replaces the earlier ADR 0026 plan to begin Python with Chat Completions; Chat Completions and LangChain remain separate work. The installed SDK is inspected directly, including public Response/Stream and APIResponse lifecycles.

Sources: [Responses create](https://developers.openai.com/api/reference/python/resources/responses/methods/create), [stream events](https://developers.openai.com/api/docs/guides/streaming-responses). These establish string/item input, instructions, generated response status and semantic streaming events. The pinned SDK defines the precise sync/async public method and close behavior; a synthetic loopback server exercises real SDK serialization/parsing, not bypass it.

`VelaResponses(client, binding)` and `AsyncVelaResponses(client, binding)` accept caller-owned configured clients. `for_turn(session_id, turn_id, timeout, cancel_event?)` returns an independent turn with create, stream, receipt, settled and close. Defaults: capture off; explicit registered project/namespace/helper/store; explicit model/base URL and memory disclosure; bounded lexical recall and final escaped framing. The helper and stream created for this operation are owned; the application model client is never closed or monkeypatched.

Input uses the last user message's text/input_text parts, or the string input. No assistant/tool/image/file conversion. Original instruction/history/options/tool arguments/attachments stay intact. Only active non-private exact namespace memories may be injected. Scope and recipient violations fail closed even if optional memory degradation is chosen. Public client.base_url is compared to the frozen declared configuration before any memory callback. A public with_options(base_url=...) client copy then fixes that request endpoint independently of subsequent mutations to the application client. Only that copy dispatches the request. It shares the caller HTTP transport, so the wrapper closes each response, releases the copy reference, and never calls close on the copy. This binds SDK URL configuration; it does not authenticate DNS, redirects, custom transport behavior or remote network identity.

Nonstream success requires completed status, no error/incomplete reason and non-empty output text. Stream capture requires the actual completed terminal response followed by EOF; failed/incomplete/refusal/error/cancel/early close create no candidate. Only filtered original user text is captured as `openai-responses` candidate; it never becomes active or a model-extracted fact. SDK and Core capability lists are checked before model dispatch. Capture uncertainty remains separate from model success, with no automatic retry. Input hash, exact project/namespace/session/turn determine replay identity.

Sync cancellation uses a caller Event or close and checks each request/stream boundary; it closes an acquired response. Before response headers the official synchronous SDK exposes no public per-request forced abort; a bounded request timeout limits that wait. It does not close the shared client, hide a worker task or claim immediate remote cancellation. Async cancellation propagates to the active await and releases acquired responses/helpers in finally. Explicit stream context ownership is required; abandoning a Python iterator alone is not proof it was closed. Model retries remain caller SDK configuration and are zero in acceptance tests.

No remote memory/analyze, real provider account, billing, WALRUS transaction or implicit model choice occurs in this slice. Loopback requests use synthetic API keys and explicit HTTP clients with environment proxy discovery disabled.
