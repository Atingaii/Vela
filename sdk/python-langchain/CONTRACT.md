# LangChain local memory contract / LangChain 本地记忆合同

The accepted provider surface is the exact official ChatOpenAI class from `langchain-openai==1.6.2`, using `langchain-core==1.6.3` and `openai==3.13.0`. Public `bind_tools` returns an official RunnableBinding subclass; the adapter reads its public bound/kwargs/config data and constructs a new ordinary RunnableBinding, rather than calling subclass execution overrides or importing private types. Public LCEL prompt/parse composition and ChatModel invoke/ainvoke/stream/astream are the consumer path.

Sources: [LangChain models](https://docs.langchain.com/oss/python/langchain/models), [BaseChatModel](https://reference.langchain.com/python/langchain-core/language_models/chat_models/BaseChatModel), [Runnable](https://reference.langchain.com/python/langchain-core/runnables/base/Runnable). Exact versions and public fields/methods are also inspected from the installed first-party packages. HTTP/SSE acceptance uses real official serialization, callbacks and message parsing against loopback, rather than a fake ChatModel class.

`VelaLangChain(model, MemoryBinding(...))` creates a manager; `for_turn(session_id, turn_id, timeout=120, cancel_event=None)` creates a `MemoryRunnable`. Binding requires a registered absolute project, exact namespace, explicitly selected helper/store, model/base URL and disclosure acknowledgement. The class exports the Runnable methods plus receipt, settled/asettled, close/aclose and sync/async contexts. Repeated sequential operations preserve source identity and counters. Concurrent work requires independent turns. Batch variants reject before any item starts. The model and all caller transports remain caller-owned.

Before filters, a snapshot validates both original root client URLs and the model name, copies JSON options/tool arguments and public mutable settings, and fixes the configured official sync/async `with_options` clients to the declared endpoint. It rebinds the exact ChatOpenAI copy to those resource clients through public `model_copy`. After memory preparation, the forwarded request timeout is reduced to the remaining deadline. Each dispatch uses only this snapshot. Plain application resolver metadata is not accepted as a substitute; DNS, redirects, callback behavior and custom HTTP routing are not authenticated. The snapshot copies application configuration but does not take ownership of caches/callbacks/rate-limiters/transports.

Only last-user text is queried/captured; system/AI/tool roles and attachments are not elevated. Active/non-private/same-project/same-namespace checks repeat after Core recall. Framing is escaped and byte-bounded. Custom filters are scoped to query/injection/capture, not a full application-prompt DLP service. A failed scope check or unsupported capture capability cannot degrade into a provider request. Ordinary recall failure can degrade only when explicitly selected.

Capture is disabled by default. When enabled, Core and SDK must advertise exact `langchain`. Successful AI text requires recognized stop termination and no refusal/tool/error; streams additionally require EOF. Only the selected filtered original human text becomes a candidate; no generated output or automatic fact extraction is saved. Human review is preserved on replay. A committed write with a missing or malformed success acknowledgement remains uncertain, with no retry. Namespace selection and source identifiers remain local provenance, not authenticated owner/delegate ACLs.

Async cancellation/close releases helper and iterator resources and retains mutation uncertainty. Sync close signals cancellation and may return while a provider call waits for its public timeout; callbacks and transport behavior can extend waits if they ignore cancellation. Explicit aclose/settled consumption establishes cleanup. The wrapper reports accepted attempts and LangChain dispatches separately; underlying cache/network/retry counts are unknown rather than guessed. No real account, remote service, wallet or model-quality claim is involved in these tests.

Independent consumer review of the retained v1 wheel found two defects: mixed string/dictionary text blocks changed order in query/capture, and default header/query dictionaries remained shared by copied SDK clients. Four-entry-point real-helper counterexamples are retained. The next acceptance preserves text order, binds explicit copied default mappings via public set_default_headers/set_default_query, checks actual public root configuration consistency, and separately verifies sync/async callable API keys are not materialized early or frozen as generated Authorization headers. Async-only key providers are accepted only for the async entry points, without synthesizing an unsupported sync client.
