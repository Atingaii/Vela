# 模型分级与协作交付协议

本协议用于本仓库的 Codex 多代理协作。Root 负责分派、整合和最终验收；子代理共享同一工作树。它是项目内的轻量约定，不安装或启动 CCB、daemon 或新的常驻 worker。Trellis 保持 `codex.dispatch_mode: inline`。

## 分级路由

| 角色 | 实际模型与思考强度 | 适合的工作 | 验收责任 |
| --- | --- | --- | --- |
| Root | 当前可用的高能力模型 | 复杂问题、架构取舍、跨模块冲突、高风险操作、最终 UI 和发布判断 | 审核关键证据，整合并对用户负责 |
| Sol | `gpt-6-sol` / `max` | 边界明确的中等实现、局部设计与修复 | 自查所属文件及定向测试，向 Root 报告 |
| Luna | `gpt-6-luna` / `max` | 明确局部任务、夹具、文档；被指定为唯一重测试者时执行大规模测试并整理结果 | 给出可复查的结果和失败证据 |

路由由任务的风险和依赖决定，不凭文件数量机械分配。Root 可直接完成短任务；只有可独立推进的有界工作才分派。新建代理时按上表设置模型和强度。若宿主不支持切换、槽位已满或现有会话不能重配，记录**实际**模型与强度并继续合理工作或等待空位；不得在提示词里冒充 Sol/Luna/Max。本协议制定时已有的 Sol High 会话仍按其实际身份记录。

后续新代理已有实际按 `gpt-6-sol` / `max` 与 `gpt-6-luna` / `max` 分派的批次。早先无法原地重配的 Sol High 会话及其证据仍保留为历史批次，不回溯改写为 max。

## 分派前的摘要

每个子任务由 Root 给出一份可执行摘要，至少包含：

```text
task_id: 逻辑子任务的稳定 ID
request_id: 本次投递/尝试的唯一 ID
base_sha: 分派时的 Git HEAD（另列已知未提交改动）
owner: 唯一可写文件或明确的代码区段；说明共享文件的协调人
goal: 具体行为和完成边界
dependencies: 上游接口、其他代理交付及其等待条件
acceptance: 可观察结果、定向测试、需由 Root 执行的检查
time_budget: 本次预期投入与检查点；到时先报告状态，不自动重试
actual_runtime: 已确认的模型/强度与可用工具；未知则注明待核
```

同一文件的交叉修改须先划分区段并互相通报。所有代理保留别人已写的内容，不重置共享工作树；重型构建由唯一执行者串行运行：Cargo `jobs=1`、Rust 测试 `threads=1`、Playwright `workers=1`。Root 可指定测试代理为唯一执行者，但同一时刻不得有第二个重型测试或构建。并行子代理最多 **3 个**（Root 另计）；无空槽就排队或由 Root 自行处理，不创建隐藏 worker。

## 结果先报摘要

子代理交付先给结论，再给可查证据，至少包含：

```text
task_id / request_id / base_sha / actual_runtime
changed_files: 本次实际修改的文件；只读任务写“无”
behavior: 已实现或确认的行为，以及关键判断
tests: 命令、退出码、日志路径；未运行要写原因，不能把语法检查称作构建
unverified: 尚未验证的平台、真实账号、UI 或边界
blockers: 具体阻塞及是否仍在运行；没有则写“无”
next: Root 可以直接执行的下一步
```

长日志留在明确的本地路径，摘要只摘关键错误与结果；不得把 token、Cookie、真实会话内容写入消息或日志。Root 默认先看摘要与差异，仅对高风险、所有权冲突、失败根因和最终 UI 深入检查；最终验收仍由 Root 完成。子代理不能用“已写入口”“已编译”代替功能或实机验收。

## 投递、超时与重试

投递成功仅表示请求被接受，**不等于执行完成**。Root 应区分已接收、运行中、已完成、明确失败和状态不明；只有可核对的终态结果才可并入验收。超过 `time_budget` 或工具等待超时先记为“待检查”，查看代理状态、当前改动与日志；超时本身不是失败，也不自动重发任务。

`time_budget` 是投入上限，不是必须用满的时长。定向测试通过后，只有新改动、失败或未解决的具体疑点才追加测试；时序回归需重复时先限定次数，不为填满预算反复跑相同套件。

重试前核对 `task_id`、最新 `request_id`、`base_sha`、工作树和代理实际进度。已有上下文与改动时向同一任务发送续做说明；从未进入执行上下文且没有副作用时才重投原请求。新的尝试保留同一 `task_id`，分配新 `request_id` 并记录新的基线。不得盲目重复会安装、发布、写凭据、提交或更改外部状态的步骤；明确失败或阻塞须连同证据交给 Root 决定恢复方式。

以上是从固定版本上游的[超时与重试契约](https://github.com/SeemSeam/claude_codex_bridge/blob/2cc7341ee27a4362a0f63d5e52d8a29c6140a780/docs/agent-message-timeout-retry-contract.md)及[通信章节](https://github.com/SeemSeam/claude_codex_bridge/blob/2cc7341ee27a4362a0f63d5e52d8a29c6140a780/docs/manuals/developer-guide/chapters/04-communication.tex)提炼的项目协作原则；不引入其 CLI、daemon、消息账本或自动重试实现。
