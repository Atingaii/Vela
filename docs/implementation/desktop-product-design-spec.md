# Vela 桌面端产品与交互设计规格

状态：V3 已通过列明的 38 项本机浏览器检查及原生交互切片；见 [本轮实施与证据](desktop-product-refinement-2026-09-14.md)。完整产品与参考覆盖验收仍未通过。

## 设计目标

用户首先要看懂当前项目发生了什么，找到需要自己判断的事项，再进入详情处理。视觉参考 ChatGPT 桌面端的轻侧栏、中性配色、克制描边、圆角菜单和舒展阅读区；功能结构依据 Vela 的实际任务，不将工程功能伪装成聊天。

避免另一次只改皮肤：先固定每页首要任务、默认信息与操作位置，再落实组件和验证。保留既有数据、工程边界和真实能力，不为视觉简洁删除功能或隐去重要失败。

## 品牌统一与语义设计（本轮补充）

ChatGPT 提供阅读与交互锚点；Vela 官网的细网格、橙色重点、工程排版构成自己的品牌。生成的桌面概念图只帮助比较布局，不作为交付截图，也不照搬其中过大的标题或虚构数据。

- **色彩**：白色主阅读区、近白侧栏、深色正文；暖橙用于当前导航和关键创建入口。代码检查、文件、定时任务等图标可用低饱和靛蓝、琥珀、青绿底色；这些颜色表达类型，不表达执行成功。官网保留细网格，客户端去除页头装饰网格，让内容与任务成为主视觉。
- **图标**：从实际工作流触发器和工具类型确定图标。`git.*` 用分支，`file.write` 用文档，`shell.*` 用终端，定时/监听分别用时钟/观察，混合编排保留连接图。不按标题猜能力，不随机换色；同类型用同图标帮助识别。
- **下拉控件**：项目选择强调文件夹与作用域；数据筛选采用轻描边紧凑控件；动作菜单带语义图标和清晰动词。保留原生 select 的键盘/VoiceOver 行为，不为皮肤替换成缺乏可访问性的模拟控件。收起侧栏时仍显示可返回项目选择的短范围标签。
- **工具调用**：能识别的命令首先显示原始命令并支持复制与高亮，输入/输出分别呈现。原始日志与完整参数可折叠查看；未观察到输出不能标成执行成功。未知格式完整降级显示，不执行内容，不自动加载外部链接。
- **额度**：参考 CodexBar 的剩余优先、窗口/重置时间、观测新鲜度模式。账户额度和项目 Token 分开。没有数据时说明如何连接；旧数据标明旧，解析失败保留上次成功记录。只呈现后端确实返回的提供方与窗口，不用示意数值填真实界面。
- **官网图片**：实际操作由当前原生截图说明；小黑插图用于解释跨会话保留知识。图中不嵌入单一语言文字，说明与替代文本分别本地化；图片按需加载。概念图不放入客户端，不引入动画或后台渲染。

资源目标以低空闲 CPU、无累积后台任务为先；用户接受约 100–200 MB 占用。仅用实测报告数值，不将总系统负载归因于 Vela，也不为了数字更小牺牲可读性。

## 页面安排

| 页面 | 用户首先要完成的事 | 首屏信息 | 首要操作 | 次要信息与操作 |
| --- | --- | --- | --- | --- |
| 会话 | 找到并继续理解一段工作 | 搜索、提供方/状态筛选、会话名称、项目、最近活动 | 打开会话；无项目时连接项目 | 刷新与导入在菜单；模型循环、历史各有独立视图；详情先读消息后查看计划/关系 |
| 工作流 | 找到已有自动化并确认它会做什么 | 名称、短摘要、触发方式、步骤数、启用状态 | 点击名称查看定义；页面保留新建 | 运行、试运行、编辑在条目菜单；批量校验/规划/模板在页面菜单；运行记录/排期/产物/健康各自显示相应信息 |
| 记忆 | 找到可复用知识并审阅候选 | 生命周期筛选、名称、短正文、来源、状态 | 打开记忆详情；新建保留明确入口 | 问答为独立入口；导入导出、索引、召回测试和复用设置在工具菜单；归档/替代在条目菜单 |
| 配置与资产 | 知道项目用了哪些配置以及有无问题 | 分类、可读名称、项目相对位置、诊断 | 扫描；点击条目阅读配置 | 审计/位置目录在菜单；完整路径、历史、差异、关系在详情 |
| 待办审批 | 判断一个具体变更是否可以执行 | 动作意图、影响项目、目标、完整可滚动内容预览 | 同一审批中的拒绝与批准 | 冻结参数/哈希折叠；决定前始终可查看原文；不得把过期/失败当成功 |
| 用量 | 分清已观察到的用量与剩余额度 | 日志统计、提供方观察时间、额度状态 | 提供方/时间范围筛选（已有支持范围内） | 不将缺失值显示成零；原始数据与来源诊断折叠；不虚构费用 |
| 调优 | 阅读一条有证据的改善建议 | 问题摘要、证据数量、状态 | 查看建议；页面可触发分析 | 模型规划在页面菜单；应用/撤销必须在证据与差异之后 |
| 对照实验 | 判断一次变更有没有改善 | 实验名称、状态与结论、基线/候选摘要 | 查看实验；新建实验 | 完整指标与输出在详情，回归独立视图；不把未运行和不确定显示为通过 |
| 设置 | 修改偏好或管理本地连接 | 常规、通知、连接与自动化、数据与隐私分类 | 保存偏好（语言保持现有即时保存语义） | 守护进程/连接器放对应分类；切换分类保留未保存草稿 |

## 内容长度与排版规则

不存在适用于中文、英文和不同窗口的统一“标题字数标准”。下面是本产品的可验证规则，依据实际可用宽度处理，不截断源数据。

- 集合列表标题一行，超出宽度尾部省略。HTML 保留全文，按钮的无障碍名称和悬停标题为完整名称；详情标题允许换行。不给标题字段新增破坏兼容性的字符限制。
- 摘要最多两行；使用者先扫描意义，进入详情后阅读完整内容。不自动改写用户正文，不将隐藏内容当作已阅读。
- 状态与菜单不参与文本压缩：菜单目标固定 36×36px，标题列 `min-width:0`、`flex:1`；内容长短不能改变菜单位置或产生横向页面溢出。
- 项目列表默认展示短项目名，资产展示项目相对路径；完整绝对路径放可展开技术信息。审批目标不能被省略成无法区分的文件名。
- 详情和审批正文支持代码/Markdown；代码内部允许横向滚动，正文和页面本身不能被长行撑开。
- 内容区以 780–1000px 的有效阅读宽度为目标；正文 15–16px，辅助说明 13–14px，主标题 24–26px。宽窗口留白，窄窗口重排，不无限拉伸内容。
- 颜色承担选中、警告、失败和成功的区分；不为普通标签引入大片彩色背景。默认黑白灰，必要状态使用低饱和色。

## 操作与状态规则

- 页面级动作：默认一个首要动作，必要的高频任务可有一个次要入口，其余用带名称的菜单组织。每个菜单项有明确动词；禁止依靠图标猜测危险动作。
- 列表用于查找和进入详情。常用运行动作仍可在条目菜单直达，安全审批链保持原样。不是通过移除功能达到“简洁”。
- 标题很长时显示完整 tooltip 与可访问名称。摘要省略只适用于浏览集合，不能用于用户批准的变更内容。
- 菜单支持点击、Enter/Space、上下方向键、Home/End、Esc、点击外部关闭；靠近窗口边缘时向可用空间展开；关闭不会误关父详情/弹窗。
- 弹窗保留固定标题和底部决定，长表单只滚动正文；关闭回到来源控件。重绘不能丢草稿、切换项目后不能被旧响应覆盖。
- 空态说明当前为什么没有内容并提供相关下一步；筛选无结果区别于尚未连接项目。加载与失败必须有实际状态，不展示假数据。
- 设置分类隐藏不相关控件但不卸载草稿；语言、系统通知授权、本地后台运行分别保持各自真实语义。
- 收起侧栏后不可聚焦隐藏导航；恢复后项目范围仍清楚。键盘快捷键集中于提示/菜单，不占据每一行。

## 验收方式

新版按九个页面、主要详情、弹窗、空态、错误态逐一走查。使用真实本地 helper + 隔离项目，覆盖中英、常规窗口和窄窗口、长中文/英文名称、无空格路径、菜单边缘、键盘与项目切换。测试不使用 force click 绕过隐藏入口。

记录功能结果与视觉结果分别是否通过。截图必须来自实际运行的软件，不用概念图证明功能。不将此 UI 改版冒充完整 188 项规格或 228 项参考能力全部交付。

## 实施顺序

1. 统一外壳、文本规则与菜单行为，并检查工作流这一典型长文本集合。
2. 将同一规则适配会话、记忆、配置、审批、调优、实验；用量保留必要数据表而非一律卡片化。
3. 完成设置分类、详情、弹窗和状态反馈；保留底层边界。
4. 本机真实交互、双语与长文本回归，先目视再冻结截图与构建，记录仍未验收的能力。
