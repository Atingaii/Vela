# ADR 0002：系统通知投递与可测试的本地策略

- 状态：Accepted
- 日期：2026-09-12

## 背景

第二轮产品优化要求适当的通知音效。FR-05 要求审批、完成、错误可分别关闭，常规运行和工具事件保持安静。现有原生壳自行比较界面查询结果：项目切换、首次历史导入和批量状态变化可能产生误报，且 UI 难以直接执行纯逻辑回归测试。

## 决策

沿用 macOS `UNUserNotificationCenter`，随包分发三个原创短 PCM WAV，以 `UNNotificationSound(named:)` 指定。声音交给系统通知机制，遵循系统通知和声音配置；不增加播放器进程、网络素材、常驻音频服务或 Critical Alert。原生通知总开关仍默认关闭；声音与三种事件类别分别保存布尔偏好，默认开启但受总开关控制。

通知去重和分类放在不产生 UI 或副作用的 `VelaCore.NotificationPolicy`，原生壳复用同一逻辑。它只消费标记为 `notificationScope="*"` 的全局 dashboard，按数据种类分别建立静默基线。筛选项目的渲染查询不改变全局基线；已关闭的事件仍被消费，重新开启不补发。历史首次导入的完成/错误记录不推断成新发生事件。同批事件按类别聚合。每类记录保留最多 2,048 个状态；被淘汰记录使用各自来源的时间水位避免再次出现时重复提示。水位是保守抑制：迟到且早于已淘汰记录的首次事件可能不通知，原始记录仍可见。

2026-09-12 实现补充：本次新建的 Workflow 可能在两次全局轮询之间完成。若首次观察时 Run 已完成或失败，Vela 自己保存的 `createdAt` 位于基线到当前观察时间之间，仍应通知。新发现会话的 `createdAt` 是索引时间，不能采用相同推断。Parser 为 `lastActivity/startedAt` 增加 `provider/ingestion_fallback` 来源标记；首次出现的会话待审批仅接受基线后、非未来的 provider 时间。旧索引缺标记、缺日期、无效日期、索引回填时间仍保持静默，已导入终态会话也不因此补发完成通知。来源标记说明时间来自日志，不证明进程存活。

聚合事件显式提供 `sources`、`spansProjects` 与 `isAggregate`。多条事件清空 `recordID`，跨项目清空 `project`，混合来源使用 `source="mixed"`；原生路由应展示相应全局列表或来源选择，不能拿第一条事件的项目和对象代表整组。单条事件保留原本对象定位。

`VelaPreferences` 统一默认值与向后兼容，旧偏好保留，新布尔补默认值。保存拒绝未知字段与数值 `0/1`，原生壳可在请求系统权限前调用相同验证方法。Renderer 仍无通用文件、声音文件路径或任意通知投递接口。

## 取舍

- 系统投递保持低常驻成本并遵循系统行为；应用不能保证在关闭通知、静音或专注模式下发声。
- 使用独立纯逻辑策略使首次基线、项目筛选、分类开关和去重可在真实核心测试中覆盖；原生展示、权限弹窗和音频最终听感仍需在 macOS 应用包中验证。
- 状态只在应用运行期间保留，重启先建立静默基线，避免将离线历史当作实时完成。它不是可靠消息队列或永久投递账本。
- WAV 使用 16-bit mono、每个 0.05–1.5 秒、最大 128 KiB 的发布约束。打包只接受三个固定文件名并验证 PCM 帧完整性；不把任意音频目录放进发布包。

## 重新评估条件

只有需要跨设备通知、应用退出后投递、用户音色自定义或可恢复事件投递保证时，再审视数据所有权和投递机制。视觉重构不改变现有本地数据及受限 RPC 边界。

## 依据

- `Tests/VelaCoreTests/NotificationTests.swift` 与 `scripts/test-release-resources.py` 覆盖策略和资源边界；执行结果由验证文档记录。
