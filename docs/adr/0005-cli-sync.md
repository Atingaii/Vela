# ADR-0005 · 多 CLI 配置适配与可恢复写入

- 状态：Accepted
- 日期：2026-09-22

Vela 维护中立资料库，通过三个适配器生成用户级 CLI 配置，不代理模型请求。供应商按协议绑定 CLI，不能把 Anthropic、Responses 和 Gemini API 互相视为兼容。MCP 只转换共有 stdio / HTTP 子集；OAuth 继续由 CLI 处理。Skill v1 采用共有 name/description frontmatter 与指令正文，不声称已可迁移带平台专有脚本的所有技能。

每次操作经历：选择目标 → 预览路径及目标字段摘要（隐藏秘密）→ 用户应用 → 检查原字节是否改变 → 全部原文件先备份 → 同目录临时文件原子替换。解析失败、类型冲突、路径符号链接拒绝写入。Codex TOML 保留无关表与注释；JSON 保留无关键，格式可规范化。

预览存于进程内，5 分钟失效；进程重启必须重新预览。多文件不是操作系统级原子事务：已写文件遇到后续错误时尝试回滚，若又被外部修改则保留现场并报告备份路径。文件检查与替换仍存在极短的跨进程竞争窗口，要求关闭会改写配置的 CLI；不宣称解决所有外部写入并发。

Vela 资料库仅保存环境变量名。Codex 引用 env_key；Claude/Gemini 本地配置格式需要认证值，应用时读取 Vela 继承环境、写入 CLI 私有文件、预览不返回秘密。新文件/备份使用 tempfile 私有默认权限，现有文件保留原权限。凭据备份不得上传 Git。

删除资料库定义不自动删除目标 CLI 中已同步的配置，避免误删独立维护的项目。需要恢复时用对应备份还原；自动逆向导入、同步删除与完整技能包将在后续增量中实现。
