# 后续规划

## 已实现的第一、第二项的后续增量

- 第三方边缘插件分发：先明确权限模型、沙箱、更新与资源限制，再决定 WASM 或隔离进程。不在 v1 加载未知原生库。
- 完整技能包：复制 scripts/references/assets，声明平台能力；冲突比较、逆向导入、可恢复同步删除。
- 用量来源：Gemini、自定义 CLI 目录、多账户、跨设备；缓存增量索引与供应商账单对账。
- 供应商：连通性检查、凭据操作系统保险库、套餐周期更细的费用模型。避免把本地估计当正式计费。
- 继续对齐 Codenotch Swift 主线未包含于现有 Tauri 移植的集成；按兼容性矩阵逐项迁移。

## 第三项 · 会话观测与改进建议（仅规划）

参考 [Blume](https://blume.codes) 的会话分析方式：用户选择本地会话 → 显示将分析的内容与脱敏预览 → 统计失败重试、上下文膨胀、工具调用与 token 成本 → 生成带证据的建议 → 用户审阅后才能改动 prompt / skill / MCP 配置。

默认本地提取结构化事件，先做无需 LLM 的指标。远程模型分析必须由用户指定提供方并确认发送范围，不默认上传会话、代码、路径或凭据。验收以错误归因准确率、用户能定位证据和建议可撤销为准，不以“建议数量”衡量。

## 第四项 · 跨 Agent / 会话记忆（仅规划）

先定义可审阅交接包：目标、当前状态、已作决策、文件/提交引用、待办、置信度与来源。区分临时会话摘要、项目事实、个人偏好；以项目命名空间隔离，支持过期、纠错与删除。

提供 MCP 读取接口与文件导出适配，由各 Agent 显式载入。写入采用提案、去重、冲突审阅，禁止会话自行把不可信网页内容提升为永久指令。先本地存储与可导出格式，再讨论远端同步、加密、团队权限。

验收：在 A Agent 结束后，B Agent 能用同一交接包准确恢复任务；引用可以追溯；删除能影响后续检索；冲突不会静默覆盖。没有完成这些边界前，不宣称“无缝共享所有记忆”。
