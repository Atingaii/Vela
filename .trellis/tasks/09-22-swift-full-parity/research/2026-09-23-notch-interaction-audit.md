Scope: sidebar geometry, moving, hover, display selection, fullscreen, drop-zone preview, and handles. This records source comparisons, not native visual acceptance. The macOS desktop was locked during this pass; no native interaction or screenshot was claimed.

- `NotchViewModel.swift` `leadingExtent`/`trailingExtent`, `NotchPlacement.panelFrame`, and `NotchWindowController.beginMove`/`applyMove`: the Vela Alt-drag origin previously clamped the full panel, including transparent card slack. `main.rs` now uses the visible shape plus source handle extents in placement and drag. - `NotchWindowController.swift` hover folding: Vela previously let a just-expanded pill remain open when changing from always visible to on-hover. `notch.html::applyUiFlags` now folds immediately on that mode change and when revealing a formerly hidden on-hover notch.

Vela's prior rounded rectangles and static dimensions were replaced in `dropzones.html`/`dropzones.rs` and `notch.html::pillShapes()` with the source contour and source geometry for all four edges; joined top preview uses hardware resting depth.
- `SettingsHandle.swift`, `MoveHandle.swift`, and `NotchViewModel.swift:333–465`: a hardware-joined top bar requires convex quarter turns, the drawn corner radius, a separately offset resting arc, and independent round hit points for the arc and button. Vela's previous always-concave flare-centre handle has been replaced in `notch.html::placeHandles`, `handleArc`, `near`, and `reportHot`. Normal four-edge parameters return when the bar is no longer joined. Dedicated UI assertions cover 0.8, 1.0, and 1.2 zoom and move-handle removal; only syntax/diff checks have run locally so far.
